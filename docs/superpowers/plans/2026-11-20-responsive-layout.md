# Responsive Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the LOQRS home page collapse to a phone with no horizontal scrolling, serve a mobile-appropriate locker graphic below 40rem, stack the coupon field, and stack the guide.

**Architecture:** Two hard-coded container widths become fluid, which lets every section below them reflow. A single 40rem breakpoint drives the layout changes and the `<picture>` source swap. The locker row's two wide raster images become one pre-composed desktop image plus one pre-composed three-locker mobile crop, generated by a committed script so the derivation is reproducible.

**Tech Stack:** Astro 7, SCSS (`sass`), graffiti (`@drop-in/graffiti`) for interactive elements, `sharp` for image compositing, `agent-browser` for measurement.

**Spec:** `docs/superpowers/specs/2026-11-20-responsive-layout-design.md`

## Global Constraints

- Single breakpoint: `40rem` (640px). No other media queries.
- Graffiti stays the library for interactive elements. No overrides of graffiti component CSS; only custom properties and the component's own wrapper width.
- No JavaScript for breakpoint detection. CSS and `<picture>` only.
- Composite assets are generated by `scripts/build-lockers.mjs` and committed. The script is not part of the build.
- Desktop `main` becomes 1436px wide, 6px narrower than today's 1442px. That is the documented consequence of the fix, not a regression.
- Dev server runs on port 1217. Start with `astro dev --background`.
- Verification uses `agent-browser`; no unit test framework exists in this project.

## Review Focus

1. Viewport 641–767px: the `<picture>` serves the desktop seven-locker composite while the guide is at two rows. The composite must not overflow, and must not look like a sliver. Owner: Task 6.
2. Exactly 640px: graffiti's `.stack-mobile` requires `width < 640px`, so the form stays in a row at 640px while the picture switches to the mobile crop. The row must still fit. Owner: Task 1.
3. `.guide-step` at 320px: base size 260px inside a 200px container. Owner: Task 2.
4. `.graffiti` between 320px and 640px: in flow, must not overlap the header or the mission text. Owner: Task 4.
5. Locker row height at 1442px: 777px, against today's 817px. The row narrows from 1440px to 1386px and loses 10px of trailing blank space. Owner: Task 6.

### Task 1: Fluid containers and form width

**Files:**
- Create: `scripts/check-layout.sh`
- Modify: `src/styles/house.scss:36-43` (`div.site-border`), `src/styles/house.scss:45-63` (`main`)

**Interfaces:**
- Produces: `scripts/check-layout.sh <width> <height>` prints one line of space-separated `key=value` measurements: `vw`, `scrollW`, `rows`, `stepW`, `stepLeft`, `stepRight`, `igDir`, `igW`, `locker`, `lockerH`, `bannerDisplay`, `ctaDisplay`, `h2W`, `graffitiLeft`, `graffitiRight`. Every later task asserts against these keys.

- [ ] **Step 1: Write the measurement script**

```bash
#!/usr/bin/env bash
# Prints one line of layout measurements for the LOQRS home page.
# Usage: scripts/check-layout.sh <width> <height>
# Prerequisites: `astro dev` running on http://localhost:1217/ and
# agent-browser installed. Override with URL=... if the port differs.
set -euo pipefail

WIDTH="${1:?usage: check-layout.sh <width> <height>}"
HEIGHT="${2:?usage: check-layout.sh <width> <height>}"
URL="${URL:-http://localhost:1217/}"
SESSION="${AGENT_BROWSER_SESSION:-loqrs-responsive}"

agent-browser --session "$SESSION" set viewport "$WIDTH" "$HEIGHT" >/dev/null 2>&1
agent-browser --session "$SESSION" open "$URL" >/dev/null 2>&1
sleep 1

agent-browser --session "$SESSION" eval "(() => {
  const r = v => Math.round(v);
  const vw = innerWidth;
  const steps = [...document.querySelectorAll('.guide-step')];
  const tops = new Set(steps.map(s => r(s.getBoundingClientRect().top)));
  const ig = document.querySelector('.input-group');
  const igr = ig && ig.getBoundingClientRect();
  const igcs = ig && getComputedStyle(ig);
  const img = document.querySelector('.lockers-row img');
  const g = document.querySelector('.graffiti');
  const gr = g && g.getBoundingClientRect();
  const banner = document.querySelector('section.banner');
  const bcta = document.querySelector('.beta-cta');
  const h2 = document.querySelector('.beta-cta h2');
  const h2r = h2 && h2.getBoundingClientRect();
  return [
    'vw=' + vw,
    'scrollW=' + document.documentElement.scrollWidth,
    'rows=' + tops.size,
    'stepW=' + steps.map(s => r(s.getBoundingClientRect().width)).join(','),
    'stepLeft=' + (steps.length ? r(Math.min(...steps.map(s => s.getBoundingClientRect().left))) : 'n/a'),
    'stepRight=' + (steps.length ? r(Math.max(...steps.map(s => s.getBoundingClientRect().right))) : 'n/a'),
    'igDir=' + (igcs ? igcs.flexDirection : 'n/a'),
    'igW=' + (igr ? r(igr.width) : 'n/a'),
    'locker=' + (img ? img.currentSrc.replace(location.origin, '') : 'n/a'),
    'lockerH=' + (img ? r(img.getBoundingClientRect().height) : 'n/a'),
    'bannerDisplay=' + (banner ? getComputedStyle(banner).display : 'n/a'),
    'ctaDisplay=' + (bcta ? getComputedStyle(bcta).display : 'n/a'),
    'h2W=' + (h2r ? r(h2r.width) : 'n/a'),
    'graffitiLeft=' + (gr ? r(gr.left) : 'n/a'),
    'graffitiRight=' + (gr ? r(gr.right) : 'n/a')
  ].join(' ');
})()" 2>/dev/null | tail -1 | tr -d '"'
```

- [ ] **Step 2: Make it executable and confirm the failing state**

```bash

```

Expected: the 1442 run reports `scrollW=1492`, and the 390 run reports `scrollW=1492 rows=1`. Both fail the goal, because the page is wider than the viewport at every width.

- [ ] **Step 3: Make the two containers fluid**

In `src/styles/house.scss`, replace the `width: 1492px` in `div.site-border` and the `width: 1442px` in `main`:

```scss

    width: 100%;
    max-width: 1492px;
    // ...existing declarations unchanged
}

main {
    width: 100%;
    max-width: 1442px;
    // ...existing declarations unchanged
}
```

- [ ] **Step 4: Make the form wrapper fluid**

In `src/components/SignUp.astro`, replace the scoped rule:

```css
.input-group {
    width: 100%;
    max-width: 1000px;
    margin-inline: auto;
}
```

The `max-width` keeps the desktop form at 1000px, which is narrower than its container, so the design's fixed-width bar survives on desktop while the group shrinks on mobile. `margin-inline: auto` centers the capped group; without it the group sits at the left edge of its parent, which is where the current fixed `width: 1000px` rule puts it.

- [ ] **Step 1: Confirm the failing state**


- [ ] **Step 2: Fix the invalid display values and the width chain**

In `src/styles/house.scss`, in `section.banner`, change `display: flexbox;` to `display: flex;`.

In `section.banner div.beta-cta`, change `display: flexbox;` to `display: flex;`, change `align-items: center;` to `align-items: stretch;`, and add `width: 100%;`.

In `section.banner h2`, add `margin-inline: auto;` after `width: 60%;`.

`align-items: stretch` is what makes the form wrapper fill the width. With `center`, the wrapper shrinks to fit its content and the input-group's `width: 100%` resolves against a shrinking parent. `margin-inline: auto` centers the 60%-wide headline box instead of relying on the flex alignment. The input-group needs no change here: Task 1 already gave it `margin-inline: auto`, which centers it once the wrapper is full width.

- [ ] **Step 3: Add the mobile headline rule**

At the end of the banner block in `src/styles/house.scss`:

```scss
@media (max-width: 40rem) {
    section.banner h2 {
        width: 100%;
    }
}
```

- [ ] **Step 3: Write the generation script**

```js
#!/usr/bin/env node
// Builds the locker-row composites used by src/components/LockersRow.astro.
// Run after changing lockers-row.png or lockers-floor.png:
//   node scripts/build-lockers.mjs
import sharp from 'sharp';

const SRC_ROW = 'public/images/lockers-row.png';
const SRC_FLOOR = 'public/images/lockers-floor.png';
const OUT_DESKTOP = 'public/images/lockers-row-composite.png';
const OUT_MOBILE = 'public/images/lockers-row-mobile.png';

// The row is 1443 wide. The floor is 1431 wide and is stretched to the row
// width, matching what the old markup did with width="1443".
const WIDTH = 1443;
const ROW_HEIGHT = 557;
const FLOOR_HEIGHT = 262;
const OVERLAP = 10;

// Locker seams in the row, measured from the source. 430 to 1048 spans
// exactly three doors, so the mobile crop has no half-panel at either edge.
const MOBILE_LEFT = 430;
const MOBILE_WIDTH = 618;

const composite = await sharp(SRC_ROW)
  .resize({ width: WIDTH, height: ROW_HEIGHT, fit: 'fill' })
  .extend({ bottom: FLOOR_HEIGHT - OVERLAP, background: '#215' })
  .composite([
    {
      input: await sharp(SRC_FLOOR)
        .resize({ width: WIDTH, height: FLOOR_HEIGHT, fit: 'fill' })
        .toBuffer(),
      top: ROW_HEIGHT - OVERLAP,
      left: 0,
    },
  ])
  .png()
  .toFile(OUT_DESKTOP);

await sharp(OUT_DESKTOP)
  .extract({ left: MOBILE_LEFT, top: 0, width: MOBILE_WIDTH, height: composite.height })
  .png()
  .toFile(OUT_MOBILE);

console.log(`${OUT_DESKTOP} ${composite.width}x${composite.height}`);
console.log(`${OUT_MOBILE} ${MOBILE_WIDTH}x${composite.height}`);
```

The mobile crop is cut from the finished desktop composite rather than from the two sources, so the floor alignment is guaranteed by construction.

- [ ] **Step 2: Replace the two images with a picture element**

```astro
---
// Composites are generated by scripts/build-lockers.mjs. Re-run it after
// changing lockers-row.png or lockers-floor.png.
---
<picture>
    <source
        media="(max-width: 40rem)"
        srcset="/images/lockers-row-mobile.png"
        width="618"
        height="809"
    />
    <img
        src="/images/lockers-row-composite.png"
        alt="A row of lockers"
        width="1443"
        height="809"
    />

```

The `width` and `height` attributes on the `<source>` matter: the browser uses them for the aspect ratio when that source is selected, so the mobile crop does not cause a layout shift against the desktop composite's 1443:809 ratio.

```scss
}
```

`<picture>` is inline by default and its child `<img>` is block, which leaves the wrapper generating a stray inline box. One declaration removes it.
